## Bug #1: Duplicate Physics Processing (CRITICAL)

### Problem

Both `PhysicsSystem` and `Player.on_tick()` were applying gravity and integrating velocity, causing:
- Gravity applied **twice per frame** with different constants (0.4 and 0.7)
- Velocity applied **twice per frame** → 2x movement speed
- All physics tuning broken
- Player moves 16 units/frame instead of 8 units/frame

### Root Cause

Lines 198-227 in `entities/player.py` duplicated physics code that already existed in `PhysicsSystem`.

### Fix Applied

**File:** [entities/player.py](../entities/player.py)

Removed duplicate physics processing (lines 198-227):
- Deleted gravity application code
- Deleted velocity integration code
- Added comment explaining physics is handled by PhysicsSystem

```python
# NOTE: Physics integration (gravity, velocity) is handled by PhysicsSystem
# DO NOT duplicate physics processing here - it causes 2x movement speed
# PhysicsSystem runs at priority 60, before player mechanics at priority 50
```

### Impact

- ✅ Physics now applied once per frame
- ✅ Movement speed correct (8 units/frame max)
- ✅ Gravity consistent (0.4 from PhysicsSystem)
- ✅ All physics tuning works as intended

### Critical Follow-up Fix

**Problem:** After removing duplicate physics processing from Player.on_tick(), the player stopped falling and moving entirely.

**Root Cause:** The player entity was never registered with the EntityManager, so PhysicsSystem couldn't process it.

**Fix Applied:**

**File:** [demo_game.py](../demo_game.py:429-433)

Added player entity registration after player creation:
```python
# Add player entity to entity manager so PhysicsSystem can process it
player_entity = entity_manager.create_entity(
    entity_type=EntityType.PLAYER,
    physics=player.state.physics
)
```

Also added coyote time management back to [entities/player.py](../entities/player.py:198-204):
```python
# Ground coyote time management
# Track when player leaves ground to enable coyote jump
was_on_ground = getattr(self, '_was_on_ground', self.state.physics.on_ground)
if was_on_ground and not self.state.physics.on_ground:
    # Just left ground, start coyote timer
    self.state.coyote_time = 0.12  # 120ms grace period
self._was_on_ground = self.state.physics.on_ground
```

**Result:** Player now falls correctly, responds to movement input, and all physics work as expected.

### Additional Follow-up Fix #2

**Problem:** Wall jumps stopped working, and player could glitch through walls by changing direction while pressed against them.

**Root Cause:** Two-part issue:
1. Player.on_tick() was calling `collision_system.check_and_resolve()`, but CollisionSystem ALSO processes all entities via TickEvent, causing duplicate collision processing and state overwrites
2. CollisionSystem ran at priority 45 (AFTER Player.on_tick at priority 50), meaning player mechanics used stale collision state from the previous frame

**Fix Applied - Part 1:**

**File:** [entities/player.py](../entities/player.py:210-215)

Removed duplicate collision processing:
```python
# NOTE: Collision detection is handled by CollisionSystem
# DO NOT duplicate collision processing here - it causes state overwrite issues
# Execution order: PhysicsSystem (60) -> CollisionSystem (55) -> Player.on_tick (50)
# CollisionSystem processes the player entity registered in entity_manager
# Player mechanics now use CURRENT frame's collision state (not previous frame)
```

**Fix Applied - Part 2:**

**File:** [systems/collision_system.py](../systems/collision_system.py:42-44)

Changed CollisionSystem priority from 45 to 55 so it runs BEFORE player mechanics:
```python
# Subscribe to tick events
# Priority 55 runs BEFORE Player.on_tick (50) so collision state is current, not stale
self.event_bus.subscribe(TickEvent, self.on_tick, priority=55)
```

**New Execution Order:**
1. PhysicsSystem.on_tick (priority 60) - applies physics/velocity
2. CollisionSystem.on_tick (priority 55) - detects/resolves collisions, updates flags
3. Player.on_tick (priority 50) - runs mechanics with CURRENT collision state

**Result:**
- ✅ Wall jumps work correctly (on_wall flag is current, not stale)
- ✅ Wall glitching fixed (collision resolved before player mechanics)
- ✅ on_wall and wall_dir flags update correctly
- ✅ No more rapid state swapping/oscillation

## Bug #2: Door Port Index Mapping (CRITICAL)

### Problem

Door ports were using tile indices (0-159) directly as zone indices (0-15):

```python
# BEFORE - WRONG
zx, zy = edge_zones[min(len(edge_zones) - 1, port.center_tile)]
# port.center_tile could be 80, clamped to 15
```

This caused:
- All doors to cluster at zone index 15
- Door distribution across room edges broken
- Rooms appearing to connect but doors in wrong positions

### Root Cause

Line 243 in `systems/zone_planning.py` - missing conversion from tile coordinates to zone coordinates.

### Fix Applied

**File:** [systems/zone_planning.py](../systems/zone_planning.py:243-245)

Added proper tile-to-zone conversion:

```python
# Convert tile index to zone index (each zone = 10 tiles)
# port.center_tile is in range 0-159 (tiles), need 0-15 (zones)
zone_index = min(len(edge_zones) - 1, port.center_tile // 10)
zx, zy = edge_zones[zone_index]
```

### Impact

- ✅ Doors now placed at correct positions along room edges
- ✅ Door distribution works properly across all 6 world shapes
- ✅ Room connections visually align with connectivity graph

Zone planning system created zones but didn't emit `AnchorCandidate` objects for the anchor resolution system.

### Fix Applied

## Bug #5: BFS VOID Walkability (MEDIUM)

### Problem

BFS pathfinding in zone planning treated VOID zones as walkable:

```python
# BEFORE - WRONG
if roles[ny][nx] == Z_FILL:
    continue  # Only skipped solid zones
# VOID zones treated as walkable!
```

This caused:
- BFS creating "bridges" across empty space
- Room layouts passing validation despite being unplayable
- False connectivity guarantees

### Root Cause

Line 396 in `systems/zone_planning.py` only checked for Z_FILL, not Z_VOID.

### Fix Applied

**File:** [systems/zone_planning.py](../systems/zone_planning.py:395-397)

Updated BFS to skip both solid zones AND voids:

```python
# Skip solid zones and voids (not walkable)
if roles[ny][nx] in (Z_FILL, Z_VOID):
    continue
```

### Impact

- ✅ BFS only uses actually walkable zones
- ✅ Connectivity validation more accurate
- ✅ Room layouts guaranteed playable
- ✅ No floating platform paths

### For Developers

If you were previously tuning physics:

**OLD (Don't do this):**
```python

# In physics_system.py

```

**NEW (Do this):**

```python

# Example: Increase gravity

# Example: Faster dash

```

Changes apply automatically to all systems.
